
## Introduction

인간의 경험은 직접 해본 행동 뿐만 아니라 누군가에게 들은 지식, 책에서 본 정보 등으로 이루어져 있다. 저자들은 일반화가 잘된 VLA 모델 또한 다양한 출처에서 얻은 경험과 지식을 전이하여 활용할 수 있어야 한다는 가설을 세운다.

로봇이 활용할 수 있는 데이터는 세 종류가 있다.
첫째, 실제 작업과 관련된 직접적인 경험이다. 해당 연구에서는 mobile manipulator가 실제로 여러 집에서 작업을 수행한 400시간의 데이터가 여기 해당한다.
둘째, 다른 로봇, 다른 환경, 다른 도메인에서 온 데이터들이다. Mobile manipulator가 아닌 고정된 로봇 팔이 동작한 데이터, 실제 가정집 환경이 아닌 실험실에서 수집된 데이터들이 여기 해당한다.
셋째, 사람이 로봇에게 현재 상태에서 어떻게 청소해야 하는지 알려주는 단계별 텍스트 지침, 이미지 기반의 VQA, captioning, object localization 데이터 등이 여기 해당한다.

“로봇도 여러 출처의 지식을 통합해야 일반화할 수 있다”는 관찰을 바탕으로, 저자들은 위와 같은 다양한 출처의 데이터들을 모두 학습하는 VLA co-training 프레임워크를 설계하겠다고 말한다.

![[Pasted image 20260506162643.png]]
Figure 1은 $\pi_{0.5}$ 모델이 어떻게 동작하는지 간략하게 보여준다. 우측의 Robot action data 뿐만 아니라 좌측의 multimodal data들이 모델 입력으로 들어간다는 점이 주목할만 하다. Subtask commands는 큰 작업을 세부 단위로 나누는 것을 말한다. 예를 들어 "clean the room"이라는 행동은 "pick up the shirt"-"put the shirt in the laundry basket"-"pick up the pillow"... 로 쪼개질 수 있다.

## Related Work

기존에도 새로운 환경에서 VLA 모델의 일반화 성능을 확인한 연구들은 있었다. 하지만 물건을 집어들거나, 옮기는 수준의 간단한 행동에서 그쳤고 generalist robot이 해낼 것이라 기대되는 복잡한 작업은 수행하지 못했다. 또한 작업 내용이 간단하여 수행 시간 또한 1분이 채 넘지 않았으나 그런 와중에도 성공률은 높지 않았다. 저자들은 $\pi_{0.5}$ 모델이 긴 시간이 소요되는 빨래 개기, 방 청소하기와 같은 복잡한 업무를 완전히 새로운 환경에서도 잘 해냈다고 주장한다.

![[Pasted image 20260507215946.png]]
$\pi_{0.5}$는 인간이 프롬프트를 입력하면 먼저 VLM이 이를 subtask로 쪼갠다. 위 figure에서는 파란 글씨로 모델이 예측한 subtask들이 나타난다. 모델 내부의 action expert 단은 인간의 프롬프트가 아니라 VLM이 출력한 subtask를 보고 동작을 출력한다.

## Architecture

![[Pasted image 20260506170916.png]]
행동 토큰을 이산적으로 처리하는 방식은 학습 비용 면에서 매우 효율적이나 실시간 추론 환경에서 auto regressive 방식의 한계로 VLA 모델에는 적절하지 않다. 이를 해결하기 위해 다음과 같은 학습 전략을 채택한다. Pre-train 단계에서는 action expert를 붙이지 않는다. 또한 모든 데이터를 이산적으로 처리하여 단순하고 효율적으로 학습한다. Post-train 단계에서 $\pi_0$ 모델과 같이 flow match로 행동을 예측하는 action expert를 붙인다. 

이렇게 학습한 모델은 추론 상황에서 먼저 작업 일정을 쪼개서 텍스트로 출력한 high-level subtask를 생성한다. 이 subtask를 보고 action expert가 low-level action을 예측한다. 

즉, $\pi_{0.5}$ 모델은 action chunk distribution과 tokenized text output을 모두 출력할 수 있는 모델이다.

모델이 받는 입력과 그 출력을 수식으로 표현하면 다음과 같다.
$$
\pi_\theta(a_{t:t+H}, \hat{\ell} \mid o_t, \ell)
$$
$a_{t:t+H}$. 길이 H의 action chunk
$\hat{\ell}$. 모델이 출력하는 high level subtask text
$\ell$. 모델이 입력으로 받는 text
$o_t = [I_t^1, \, ..., I_t^n, q_t]$. 시점 t에서 모델에 입력할 n개의 이미지와 현재 로봇 상태(각도, 속도, 자세 등) $q_t$. 

위 식을 다음과 같이 분해할 수 있다.
$$
\pi_\theta(a_{t:t+H}, \hat{\ell} \mid o_t, \ell) 
= 
\pi_\theta(a_{t:t+H} \mid o_t, \hat{\ell})\pi_\theta(\hat{\ell} \mid o_t, \ell)
$$
이는 action distribution이 입력 텍스트 $\ell$이 아니라 subtask $\hat{\ell}$을 보고 생성되기 때문이다.

## Loss Function

$\pi_{0.5}$ 모델은 학습 중에는 이산, 연속 행동 표현을 모두 학습한다.

$$
\mathbb E_{\mathcal D, \tau, \omega}[H(x_{1:M}, f_\theta^\ell(o_t, \ell))
+
\alpha || \omega - a_{t:t+H} - f_\theta^a(a_{t:t+H}^{\tau, \omega}, o_t, \ell)] ||^2
$$

먼저 다음 항을 살펴보자.
$$
H(x_{1:M}, f_\theta^\ell(o_t, \ell))
$$
$H(\hat{y}, y)$. CE loss
$x_{1:M}$. 라벨
$f_\theta^\ell(o_t, \ell)$. 모델 예측
M개의 텍스트 토큰에 대한 CE loss를 의미한다.

그 다음 항은 flow matching action loss를 계산한다.
$$
\alpha || \omega - a_{t:t+H} - f_\theta^a(a_{t:t+H}^{\tau, \omega}, o_t, \ell)] ||^2
$$
$\alpha$. discrete loss와 continuous loss 사이의 가중치. Pre-train 상황에서는 0으로 설정하여 이산 토큰에 대한 학습만 진행한다. Post-train 상황에서는 10으로 설정한다.
$\omega$. 가우시안 노이즈 샘플
$a_{t:t+H}$. 정답 action chunk
$w - a_{t:t+H}$. 정답 vector field. 직관적으로는 부호가 반대여야 할 것 같지만 논문에서는 이렇게 일관되게 쓰고 있다.
$f_\theta^a$. action expert가 예측한 vector field
$a_{t:t+H}^{\tau, \omega}$. noise와 action 사이의 중간 action sample

중간 action sample은 다음과 같이 정의된다.
$$
a_{t:t+H}^{\tau,\omega}
=
\tau a_{t:t+H} + (1-\tau)\omega,
\quad
\omega \sim \mathcal{N}(0,I)
$$
$\tau = 0$이면 순수한 노이즈, $\tau = 1$이면 정답 샘플이 된다. [[Flow Matching]]의 OT와 같다.

## Data

![[Pasted image 20260507215854.png]]
왼쪽 5개 데이터는 pre-train, 오른쪽 5개 데이터는 post-train에만 사용된다. WD(web data)는 pre-train, post-train 모두에 사용되는데 저자들은 VLM이 웹에서 학습한 보편적 언어 지식을 유지하기 위함이라고 밝힌다.

여러 로봇(mobile-non mobile, one arm-two arms), 여러 환경의 데이터들을 하나의 포맷으로 맞출 필요가 있다.

각 데이터셋의, 각 action dimension에 대해 1%, 99% 값을 기준으로 \[-1, 1] 스케일로 정규화 한다. mix-max 정규화와 달리 극단적인 이상치에 의해 스케일이 뭉개지지 않는 선에서 대부분의 값들을 안정적인 범위 안에 넣는다. 스케일을 빠져나가는 경우의 clipping은 적용하지 않는 것으로 공식 github 코드에서 확인된다.

$\pi_0$와 마찬가지로 여러 데이터들 중 가장 큰 차원에 맞춰 전체 차원을 고정하고 해당 차원이 값이 없는 데이터셋의 경우에는 제로 패딩으로 처리한다. 실제 evaluation에 사용된 mobile robot은 다음과 같은 action dimension을 갖는다.
![[Pasted image 20260507164206.png]]
왼팔 6 DoF(6 Degrees of Freedom) 6차원
오른팔 6 DoF 6차원
왼쪽 gripper 1차원
오른쪽 gripper 1차원
Holonomic base velocity 3차원(전후, 좌우, 회전 각속도)
Torso lift 1 or 2차원(1차원은 몸통 기울기만 동작. 2차원은 몸통 기울기, 몸통 앞뒤 운동 포함)

패딩까지 포함한 전체 차원 수치에 대해서 논문에서는 명시하고 있지 않으며 github 코드에서 32차원으로 설정된 것을 확인할 수 있다.

로봇이 자신의 action/state를 표현하는 방식인 로봇 인터페이스는 크게 둘로 나뉜다.
Joint / End effector
"로봇 손을 앞으로 3cm 내밀어라"는 명령에 대해 각 인터페이스는 다음과 같이 표현된다.

Joint
표현 방식: 각 관절을 어떤 목표 각도/속도/변화량으로 보낼 것인가?
어깨를 이만큼 돌리고, 팔꿈치를 이만큼 펴고, 손목을 이만큼 조정해서 손을 앞으로 3cm 내밀어라.

End effector
표현 방식: 손끝을 공간상 어디로 보낼 것인가?
손끝을 현재 위치에서 앞쪽으로 3cm 이동한 좌표로 보내라.

여러 데이터들은 두 인터페이스가 혼재되어 있다. 따라서 모델이 현재 action label이 무엇인지 구분할 수 있도록 특수 토큰을 입력해줘야 한다.
예시)
\<control mode> joint \<control mode> put the cup in the sink
\<control mode> end effector \<control mode> put the cup in the sink

출력 차원이 \[B, 50, 32]임을 고려하여 추가로 설명해보겠다(B: Batch, 50: length of action horizon, 32: action 하나의 차원). \[B, 50, 0] 차원의 출력이 왼팔에 관한 내용을 담는다고 가정하자. 이때 입력 프롬프트로 인터페이스가 joint임이 확인되면 모델은 joint 인터페이스에 알맞는 출력값을 내놓을 수 있다. 반대로 end effector인 경우에는 모델이 해당 인터페이스에 알맞는 출력값을 내놓을 수 있다.

## Evaluation

Figure 8, 9의 실험 같은 경우 pre-train과 post-train을 모두 실행하는 것은 계산 비용이 커 pre-train 상황에서는 실제 동작 로봇과 관계없는 데이터들만 학습하고 post-train 상황에서 실제 동작 로봇의 데이터를 조절하여 학습 장소의 수를 비교하는 실험을 했다고 한다.

![[Pasted image 20260507220527.png]]
Figure 8에서 우측 초록색 in-domain은 테스트 환경을 미리 학습한 치팅 모델들이다. 반면 왼쪽의 노란색 그래프는 학습한 장소의 수가 달라지는(테스트 환경은 학습하지 않은) 모델들이다. 104곳(100%)의 장소를 학습한 모델은 테스트 환경을 미리 학습한 모델과 성능 차이가 나타나지 않는 것으로 보아 강력한 일반화 성능을 확인할 수 있다.
테스트 환경을 미리 학습했음에도 pre-train 과정이 생략된 모델은 낮은 성능을 보여 연구에서 제시한 다양한 데이터가 섞여들어오는 pre-train 과정이 일반화에 유의미함을 보여준다.
104곳의 장소를 모두 학습했지만 pre-train 과정은 생략하고 테스트 환경도 학습하지 않은 모델은 매우 저열한 성능을 보여준다. pre-train의 중요성을 다시 한 번 확인할 수 있다.

![[Pasted image 20260507221052.png]]
Figure 9는 여러 물체들을 두고 로봇이 언어 지시에 따라 적합한 물체를 집은 뒤 적절한 위치(서랍 안, 탁자 위 등)에 옮기는 문제 상황의 성능을 보여준다.
Follow는 로봇이 적절한 물체를 식별했는지, Success는 로봇이 적절한 물체를 식별함 + 적절한 위치에 옮기는 데 성공함 여부를 판단한다.
In-distribution은 학습 중 본 적 있는 물체, Out-of-distribution은 학습 중 본 적 없는 물체를 집는 문제 상황이다. 당연하게도 in-distribution 문제 상황에서 더 높은 성능을 보이는 것처럼 확인되나 104곳의 장소에서 모두 학습한 로봇은 이 간극을 거의 없애며 강력한 일반화 성능을 다시 한 번 보여준다.

![[Pasted image 20260507221405.png]]
WD. Multi modal web data는 VQA, captioning, object detection 등의 데이터를 포함한다. WD를 제외하는 것은 모델 성능에 큰 영향을 미치지 않는 것처럼 보이나 후술할 instruction following 문제에서 그 중요성이 나타난다.
ME, CE는 모두 중요한 역할을 하는 것으로 보인다. 다른 로봇, 다른 환경에서 수집된 데이터가 일반화 성능 향상에 유의미함을 보여준다.

![[Pasted image 20260507222614.png]]
Action 학습 도중 본 적 없는 물체를 집어야 하는 문제에서는 WD 데이터 또한 중요한 것으로 나타난다. ME, CE 데이터는 마찬가지로 제외되면 유의미한 성능 하락을 보여준다.

![[Pasted image 20260507222905.png]]
Figure 13에서는 action expert는 놔두고 여기에 입력으로 사용할 subtask text를 생성하는 주체를 변경하는 실험의 결과를 보여준다.
Implicit HL은 인간이 입력한 프롬프트를 subtask로 변환하는 과정없이 바로 모델에 입력하는 형태이다. 단, 훈련 중에는 HL 데이터를 본 모델이다. 즉, 훈련 중 HL 데이터를 본 것이 주요 성능 향상 요인인지, 실제 subtask를 만들고 action expert에 입력하는 것이 주요 요인인지 확인하는 실험이다. Implicit HL이 full model 바로 다음의 성능인 것을 통해 학습 과정에서 HL 데이터를 보기만 해도 모델 내부 representation이 나아진다는 것을 알 수 있다.
GPT-4 HL은 프롬프트 엔지니어링을 통해서 subtask를 출력할 수 있게 만든 실험인데 초대형 LLM보다도 3.3B 파라미터 크기의 $\pi_{0.5}$ 모델이 더 나은 성능이 나타남을 보여준다.
Human HL은 전문가가 직접 subtask를 모델에 입력해주는 실험이다.

## Limitation

여전히 실수한다.
낯선 서랍, 뻑뻑한 서랍, 카메라가 일부 가려져 full observation이 불가능한 경우, high level subtask가 산만해지는 상황에서 실패하는 모습이 두드러진다.

High level subtask가 산만해진다.
저자들은 서랍을 열고 닫는 상황이 반복되는 문제를 예시로 든다.
성공 사례:
"open drawer" → "pick up object" → "put object in drawer" → "close drawer"

실패 사례:
"open drawer" → "close drawer" → "open drawer" → "close drawer" ...

다양한 일을 수행할 수 있지만 여전히 다음 수준의 단순한 명령만 가능하다.
예시)
clean the kitchen
clean the bedroom
put the dishes in the sink
put the items in the drawer
실제 가정 환경에서 수행해야 하는 복잡한 추론을 위해서는 더 정교하고 다양한 데이터들이 필요하다고 설명한다.
예시)
깨지기 쉬운 컵은 싱크대에 넣지 말고 오른쪽 선반에 둬라.
젖은 수건은 빨래 바구니가 아니라 욕실 문에 걸어라.
내가 쓰는 머그컵은 치우지 말고 테이블 위에 둬라.

Context가 짧다.
여러 방을 오가야 하는 상황, 아까 봤던 물건을 기억해야 하는 상황, 방금 실패를 바탕으로 계획을 수정해야 하는 문제 등에서는 적절하지 않다.

Heterogeneous data source의 한 조합을 탐색한 연구로써 앞으로 더 다양한 데이터 소스들이 실험될 수 있을 것이다.

저자들은 본 연구의 데이터 조합 중 Verbal Instruction에 집중한다. 로봇 trajectory를 많이 입력하는 것보다 사람이 pre-train 모델에 대해 피드백을 해주는 것이 contextual knowledge를 알려주는 좋은 방법일 수 있다는 것이다.

## Personal

10-step flow matching은 실시간 제어를 위한 효율적 절충이지만, 이상적인 형태라고 보기는 어렵다. Action chunk를 만들기 위해 여전히 재귀적 denoising이 필요하므로, 향후 연구에서는 더 적은 step으로 action을 생성하는 방식이 중요한 최적화 방향이 될 가능성이 크다고 생각한다.
